# 核心洞察：LLM 的自知不可靠性与系统防护的二元一体

## 问题本质

所有 Agent 死循环、盲目重试、空输出后误判——这些问题的根源不是 `mkdir` 行为不当，而是 **LLM 缺少一种关键能力：对自身状态的自觉和对自身不可靠性的认知**。

```
一个不知道自己会犯错的系统，必然重复犯错。
一个不知道自己在做什么的系统，必然迷失方向。
一个不检查返回值的系统，必然对失败视而不见。
```

## 二元防护模型

解决方案是两件事的合一：

```
┌─────────────────────────────────────────────────────────┐
│                                                         │
│   认知层 (Cognitive)          技术层 (Technical)         │
│   ─────────────────          ─────────────────          │
│   让 LLM 自觉自醒             当 LLM 不可靠时            │
│   意识到自己的状态             系统兜底防护               │
│                                                         │
│   "我知道我在第几步"           "你迷糊了，我来接管"        │
│   "我知道上次失败了"           "返回值是空的，不能重试"    │
│   "我知道不能重复同样的事"      "你已经试了3次，该停了"    │
│   "我需要检查返回值"           "exit code=1，不是意外"    │
│                                                         │
│        ↓                            ↓                   │
│   自主正确决策                  强制阻止错误               │
│                                                         │
│   ───────────────────────────────────────────────────    │
│              两者缺一不可                                  │
│                                                         │
│   只有认知层 → LLM 可能不听话 (统计性质)                   │
│   只有技术层 → LLM 不成长，每次都靠系统救火                │
│   两者结合   → LLM 尽可能自主正确 + 系统兜底保证下限       │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

## 三个自知

LLM 需要三种自知能力：

### 1. 状态自知 (State Awareness)

```
❌ 没有自知: "创建一个目录" → mkdir → 忘记是否已经创建 → 再次 mkdir
✅ 有自知:   "步骤3: 确保 /tmp/app 存在"
            → 检查 checkpoints.jsonl: "步骤3之前已完成且已验证，跳过"
            → 或: "步骤3未完成，执行，保存checkpoint"
```

**实现**: `checkpoint_skip_if_completed()` — 执行前先问"我是否已经做过？"

### 2. 不可靠自知 (Unreliability Awareness)

```
❌ 没有自知: mkdir → Permission denied → "可能只是意外" → mkdir (重复×N)
✅ 有自知:   mkdir → Permission denied → 查表: E_PERM → retryable=false
            → "我不能再试同样的方法。需要替代方案。"
```

**实现**: `classify_result()` 返回 `retryable` 字段 + `DO_NOT_RETRY` 上下文注入。

这是最关键的自知——LLM 的天然倾向是乐观重试。必须**显式告诉它**：你的直觉是错的，不要重复。

### 3. 返回值自知 (Return Value Awareness)

```
❌ 没有自知: 执行命令 → 输出为空 → "命令没运行" → 重试 → 死循环
✅ 有自知:   执行命令 → 输出为空 → "空输出 = 系统灾难" → 立即停止
            执行命令 → exit=1, stderr="Permission denied"
            → "exit=1 不是意外，是权限错误" → 分类决策
```

**实现**: 
- 强制命令模式: `OUTPUT=$(cmd 2>&1); EXIT=$?; echo "EXIT:$EXIT"`
- 空输出检测: `guard_exec()` 在输出为空时注入 `E_SYSTEM_CATASTROPHE`
- Exit Code 映射表嵌入 prompt

## 当 LLM 不可靠时：系统兜底

认知层是"最好情况"——LLM 自主正确决策。但 LLM 是统计的，不可靠是常态。因此**技术层是必需的**：

```
LLM 的不可靠表现              系统兜底
──────────────────           ────────────────
LLM 忽略 prompt 规则         guard_exec 强制检查空输出
LLM 忘记已经重试过2次         checkpoint_detect_deadloop 自动检测
LLM 在长上下文中迷失           checkpoint_recover 注入明确的恢复上下文
LLM 重复同样的错误             Circuit Breaker 熔断该策略
LLM 不知道换了什么策略         strategy_router 显式列出 strategies_remaining
LLM 进程崩溃                  _fallback_error() 始终返回结构化 JSON
```

关键洞察：**系统兜底不是在 LLM 正常时介入，而是在 LLM 表现出不可靠信号时介入**：

| 信号 | 含义 | 系统动作 |
|------|------|---------|
| 同一 goal+approach 出现2+次 | LLM 可能陷入循环 | 标记 deadloop, 注入替代策略 |
| 工具返回空 | 进程可能崩溃 | 注入 E_SYSTEM_CATASTROPHE |
| 同一策略连续失败3次 | 该策略无效 | Circuit Breaker OPEN |
| checkpoint 状态与实际不符 | LLM 记忆错误 | 验证失败 → 标记需重做 |
| 长上下文 (200+ checkpoint) | LLM 可能迷失 | 日志轮转, 上下文注入精简 |

## 六层视角下的二元结构

```
技术层 (当 LLM 不可靠时兜底)
  L6 断点恢复    ← 检测死循环, 注入替代方案
  L4 优雅降级    ← 空输出兜底, 系统崩溃防护
  L3 错误分类    ← 查表: retryable? 熔断?
  L2 安全工具    ← 幂等包装, 杜绝裸调

认知层 (让 LLM 尽可能自主正确)
  L5 Pi适配      ← agents.md 嵌入: 返回值思维, 分类先于重试
  L1 根因分析    ← 理解死循环机理, 认知引导

两层不是分离的——L2/L3/L4/L6 的每一个技术防护, 都对应一条认知引导:
  ensure_directory  → "用幂等操作, 不要裸调 mkdir"
  classify_result   → "先查表分类, 不要盲目重试"
  guard_exec        → "空输出 = 灾难, 不是未执行"
  checkpoint_recover → "回退断点, 尝试替代方案, 不要重复"
```

## 最优解的特征

如果一个方案能同时做到：

1. **LLM 在能力范围内自主正确** — 会检查返回值、会分类错误、会主动切换策略
2. **系统在 LLM 失效时兜底** — 空值拦截、重试检测、策略熔断
3. **认知与技术互为镜像** — 每一条技术规则都有一条对应的 prompt 规则，互相强化

那么这就是一个**较优解**。

不是"信任 LLM"或"不信任 LLM"的二选一，而是：
**"信任 LLM 在给定的认知框架内能做出好决策，但不信任 LLM 在任何情况下都能保持这个框架。"**

所以：框架由系统强制维护，决策在框架内交给 LLM。

## 一句话总结

> **让 LLM 知道自己在哪里（状态自知）、知道自己会犯错（不可靠自知）、知道命令返回了什么（返回值自知）——同时准备好当它失去这些自知时，系统替它兜底。**
